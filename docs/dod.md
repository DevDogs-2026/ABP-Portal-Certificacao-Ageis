# Definition of Done (DoD) — DevDogs

**Proposta para aprovação pela equipe — Sprint 02 (23/10 a 05/11/2026).** Não representa uma DoD já ratificada.

Uma Issue somente pode ser marcada como concluída quando:

- [ ] Está vinculada a uma User Story, requisito ou necessidade validada pelo Product Owner.
- [ ] Seus critérios de aceite foram verificados e há evidência objetiva.
- [ ] A alteração foi versionada em branch própria e vinculada à Issue.
- [ ] Um integrante diferente do autor revisou o Pull Request, quando houver código.
- [ ] Os testes aplicáveis foram executados e os resultados registrados (inclusive testes negativos).
- [ ] Não há senhas em texto puro, credenciais, dados pessoais reais ou segredos incluídos no commit.
- [ ] O código foi integrado à branch de entrega aprovada, sem conflitos pendentes.
- [ ] A documentação de instalação, execução e rastreabilidade foi atualizada quando pertinente.
- [ ] A Issue contém links para PR, evidências, testes e artefatos correspondentes.
- [ ] O Product Owner confirmou o atendimento aos critérios de aceite.

## Adaptação por tipo de entrega

- **Frontend:** validar navegação, estados, responsividade, acessibilidade básica e aderência ao Figma.
- **Backend/BD:** validar API, persistência, integridade, segurança e cenários de erro; documentar scripts e testes.
- **Modelagem/Figma/UML:** validar arquivo editável, correspondência aos requisitos e evidência de revisão; testes de código não se aplicam.
- **Processo Scrum:** evidências datadas e links reais para backlog, Planning, Daily, Review, Retrospectiva e Burndown.

## Regra de transparência

Uma tarefa sem evidência verificável deve permanecer em revisão ou andamento. O preenchimento desta lista não substitui aprovação da equipe nem comprova execução retroativa.
