# Feedback da Sprint 1 — Portal de Certificação em Metodologias Ágeis

**Projeto:** Portal de Certificação em Metodologias Ágeis  
**Contexto:** Projeto acadêmico — 1º semestre de Desenvolvimento de Software Multiplataforma (DSM)  
**Período de referência:** Sprint 1 (28/09 a 22/10/2026)  
**Objetivo deste arquivo:** Registrar os pontos de feedback feitos pelos Ponto focal do projeto e Cliente.

> **Nota:** Este documento foi elaborada a partir dos pontos relatados pelos Stakeholders do Projeto durante a Sprint Review 01. As pontos descritos são recomendações que devem ser atendidos nas próximas Sprints.

## 1. Era esperado que o backlog e planejamento tivesse sido validado com o Cliente previamente à Sprint Review.
### Plano de ação:
Organizar a Sprint02 e o Project owner apresentar formalmente o Backlog, planejamento para execução e entrega formalmente ao Cliente.

## 2. A apresentação pessoal também é observada.
### Plano de ação:
Atentar para a vestimenta escolhida para apresentação das próximas Sprint. Considerar vestimentas mais formais, adequadas à circunstância da Sprint Review.

## 3. O vídeo de apresentação deve ter foco no Produto.
### Plano de ação:
Atentar ao material apresentado no vídeo de apresentação. Deverá ter como objetivo demonstrar os entregáveis planejados para a Sprint.

## 4. Atribuição individual em qualquer momento da apresentação.
### Plano de ação:
Menções a integrantes específicos quanto a responsabilidade de qualquer ação durante o projeto é terminantemente vetada. As menções são sempre coletivas ex.: O time, nós, todos.

## 5. A descrição do planejamento das Sprints deve constar no arquivo ReadMe
### Plano de ação:
Incluir descrição dos entregáveis planejados para cada Sprint e resumo sobre andamento do Produto.

## 6. Os indicadores de rendimento do time no Github devem ser constantemente monitorados a fim de se identificar possíveis pontos de atenção.
### Plano de ação:
Incluir nas atividades do Scrum Master, definir frequência, incluir o monitoramento frequente dos indicadores (Insights) e registrar eventuais ações necessárias para mitigar o risco à entrega planejada.

## 7. Apresentação precisa demonstrar domínio sobre a apresentação
### Plano de ação:
Agendar apresentação com o próprio time para aprimorar o domínio de todos com a apresentação, entregas, e produto.

## 8. Entregas diferentes referentes ao mesmo elemento devem apresentar correspondência e refletir os mesmo aspectos.
### Plano de ação:
Atentar para aderência dos elementos desenvolvidos das próximas entregas aos entregáveis da Sprint01.

## 8. Atentar para a organização do projeto.
### Plano de ação:
Registrar todas as ações no repositório, produtos intermediários. Utilizar o ReadMe para linkar aos arquivos relevantes.
